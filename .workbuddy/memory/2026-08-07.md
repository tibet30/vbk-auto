## 管家联系人 picker 搜索框 UI 重做

用户截图红框指出 account-editor 管家联系人 picker 的搜索框"嵌套框"怪样。

根因：`contactCardSearch` 容器 + shared.input 嵌套，但用 `.contactCardSearch :global(.input)` 试图覆盖 shared.input 的 border/圆角/height 失败——CSS Modules 把 `shared.input` 编译成带 hash 的 `.input_xxxxx`，而 `:global(.input)` 匹配不带 hash 的选择器，结果 input 保留了 shared.input 自己的 1px 边框 + 8px 圆角 + 36px 高度，与容器的 border-bottom 叠成视觉双框。

改动（`views/account-editor/`）：
- `index.tsx` — input 改用 own className（`styles.contactCardSearchInput`），加清空按钮（`contactCardSearchClear`）；placeholder「按姓名筛选，输入后 300ms 自动查询」→「按姓名搜索」（300ms 由 loading 表达）；图标/loading 加 className 便于 hover/focus 着色
- `index.module.less` — 整个 `.contactCardSearch` 段重写：单层圆角带边框搜索框（`height: 36px; border 1px; bg --bg`），去掉 `:global(.input)` 改用 own className（`.contactCardSearchInput` border:0/background:transparent），focus 改用「边框变 strong + 3px teal 14% 软光晕」，加 `.contactCardSearchClear`（20×20 方形 hover --muted）

经验：CSS Modules 下用 `:global(.className)` 覆盖同样模块的类无效（hash 不匹配）；要用 own className 或 `:local(.className)` + 模块内 import。**省 token 也别省在容器+共享组件这种边界上**，双层样式本来就难维护。

补充：第二次截图仍双层框，根因是新写的 `.contactCardSearch` 自带 border+radius+bg，套在 `.contactCardPicker` 容器（也有 border+radius）外框内变双层。最终方案：search 嵌在 picker 内部、共享 picker head 的视觉层（无 border、bg transparent、hover 浅 --muted 混合、focus 时 bg teal 6% + 底部 inset 2px teal），让"搜索框"和 picker 是一个整体。

补充 2：第三轮截图仍是圆角矩形+边框的双层感。这次是全局 reset 兜底——`styles/reset.css` 里有 `:focus-visible { outline: none; box-shadow: var(--focus); border-radius: var(--radius-sm); }`。input focus 时全局给 box-shadow 和 border-radius，独立看起来就是个圆角矩形。修复：在嵌入式 input 的 own className（`.contactCardSearchInput`）里加 `border-radius: 0; box-shadow: none;`，并在 `:focus / :focus-visible` 状态下重置这两项。**嵌入式 input 的 focus 视觉要迁到父容器（`.contactCardSearch:focus-within`），input 自身不画 focus 圈**。

经验升级：嵌套容器内 input 至少有 4 个层会"画外观"——容器 bg/border、input own class、共享 input class、全局 reset/UA 样式。逐层对齐前先全局 reset 兜底是否还生效。

## "当前账号"显示"管理"排查与修复

用户反馈设置页"当前账号"显示"管理"两个字，应是 VBK 真实用户名。

根因：`src/main/infrastructure/vbk-browser.ts:checkVbkLogin` 用 DOM 抓账号名，selector `[class*="user"]` / `[class*="account"]` 太宽，VBK 后台"账号管理"/"用户管理"等菜单项的 class 名都带 user/account，**第一个命中就是菜单项**，`textContent.trim()` 剩"管理"两字。regex 兜底 `/(?:供应商|账号|用户|登录人)[:：\s]*([^\n\s]{2,24})/` 抓到"账号管理"时也会把"管理"吐出。项目里其实已经有 `current-user.ts:fetchCurrentUserInfo`（调 VBK getCurrentUserInfo API 拿真实 displayName），但 checkVbkLogin 完全没用它。

修复（`src/main/infrastructure/vbk-browser.ts`）：
- 导入 `fetchCurrentUserInfo`
- `checkVbkLogin` 重写：先 `this.page()` → `fetchCurrentUserInfo` → 用 displayName 或 loginAccount 作为 accountName；API 失败 → fallback 原 DOM 抓取，但**加 `MENU_FALSE_POSITIVES` 黑名单**（"管理"/"账号管理"/"用户管理"/"退出"等）
- 没登录时不调 page/不走 fallback，直接返回未登录

经验：DOM 抓取天然脆弱（class 命名不可控）；优先用 API/Schema 解析，DOM 只能兜底，且要白名单/黑名单 + 严格长度/类型校验。

## API Key 输入框眼睛按钮错位 bug

用户反馈设置页 MiniMax API Key 框"丑"——红框里能看到 input 边框 + 下方独立眼睛图标。

根因：`src/renderer/app/views/settings/minimax-block.tsx` 用 `shared.passInputWrap` 包 input + `shared.iconBtn` 当眼睛按钮。`shared.module.less` 里 `.passInputWrap` 只设了 `position: relative; .input padding-right: 44px`，**没有给 .iconBtn 任何 absolute 定位**。结果是按钮流式布局，跑到 input 下方独立显示，形成视觉双层。

修复：`shared.module.less` 加 `.passInputWrap .iconBtn { position: absolute; right: 6px; top: 50%; transform: translateY(-50%); width: 28px; height: 28px; }`（按钮绝对定位到 input 右内侧；同时把 iconBtn 默认的 32×32 缩到 28×28，更贴合 input height 36 的内部比例）。

经验：共享类 `passInputWrap` 这种"容器 + 内嵌控件"模式，CSS 必须把内嵌控件的定位一起定义好——只定义容器 relative 但不给按钮 absolute，等于半成品。这种 wrapper 类在仓库里只有 1 处使用，要么补全样式要么拆掉——别留隐患。

## 头像缩写优化

`src/renderer/app/state/derived.ts:accountInitial` 原是 `currentAccountName.slice(0, 1).toUpperCase()`，对 `vbk_671205` 取首字符 `V`，识别度低。改为"最后一个数字"逻辑：`currentAccountName.match(/\d(?!.*\d)/)?.[0] ?? slice(0,1).toUpperCase()`（`\d(?!.*\d)` 是 negative lookahead 找最后一个数字）。`vbk_671205` → "5"，"小璐" → 兜底 "小"（无数字），"未登录" → "未"。
