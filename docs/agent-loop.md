# 产品 Agent 循环

产品详情第一步采用双栏：左侧「方案协作」显示用户消息、AI 回复、工具调用与返回、问题列表和最终确认；右侧「审查结果」保留可编辑卡片和 JSON。顶部保留任务进度与 AI 用量。

## 运行方式

`AgentCore` 持久化用户意图，调用当前配置的模型，执行返回的工具，将真实结果追加到消息组，再继续请求模型。没有工具调用时：纯查询结束；本地修改须通过就绪检查并等待最终确认；远端写入须具备本轮全部阶段的回读证据才结束。

- `ask_user` 支持文本、单选、多选、确定/取消，服务端检查问题和答案。
- `request_approval` 创建绑定方案语义指纹、当前意图、VBK 账号和完整录入范围的审批。
- `execute_vbk_phase` 复用现有 VBK 阶段接口，一次执行一个阶段。
- 未通过「确认方案并录入 VBK」不能写入。确认成功后界面自动切换第二步。
- 新建、旧聊天和旧规划写入口均委托 Agent；旧的直接自动录入入口拒绝绕过确认。
- 用户可以在运行期间补充要求；已发出的工具执行到安全点后，剩余旧调用取消，新要求进入下一轮。暂停与废弃不会删除产品或远端草稿。

## 持久化与边界

SQLite `agent_snapshots` 保存完整事件、当前运行、待回答问题、待确认方案及不确定写入。模型上下文按完整工具调用组裁剪，界面仍可查阅完整事件。工具内部的大型查询文本有长度限制。

产品方案仍复用本地变更服务和远端镜像。Agent 正在处理或等待用户时，产品读取保护本地工作集，避免用较旧的远端快照覆盖正在编辑的内容。录入前重新获取产品绑定账号，并在浏览器互斥锁内校验当前授权。旧 `draft_saved` 不再让 Agent 的本轮任务提前完成。

启动时不自动重放未知状态的写入。未发出的调用可取消并恢复；已发出但未收到结果的写入进入不确定状态。当前自动核对仅支持已有产品编号、且远端产品编号和供应商编号一致的产品壳创建结果。其他阶段的不确定写入保持暂停，尚不支持通用的自动核对与恢复；不能把一次「继续」当作重复写入的授权。

## 代码入口

- `src/main/agent/core.ts`：循环与用户命令。
- `src/main/agent/core-*.ts`：消息协议、问题校验、快照与工具执行。
- `src/main/agent/integration-setup.ts`：模型、业务工具、账号、完成检查与浏览器启动连接。
- `src/main/agent/integration*.ts`：产品修改、审批、进度、用量和核对。
- `src/main/ipc/agent-ipc.ts`、preload、共享契约：界面协议。
- `src/renderer/app/views/workspace/agent-conversation.tsx`：左侧对话与确认。

## 验证

`test/agent` 覆盖循环、多工具协议、并发输入、授权失效、重启、指纹、完成证据和真实浏览器交互。浏览器 fixture 使用真实协作组件与模拟服务，不能替代登录后的真实 VBK 录入验收。真实平台 E2E 仍需明确目标产品和测试账号，默认不执行。
