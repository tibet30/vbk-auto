# AI 产品规划：职责与验收

本文描述 2026-10-11 重构后的正式规划路径。

## 正式入口

`main-ipc.ts` 注册 `registerPlanningV2Ipc`。开始、继续、重跑和采用行程都转换为 Agent 意图；IPC 不直接执行另一套规划循环。

```text
规划入口 → Agent 的持久化调度与事件
         → 准备阶段规则 / 下一步动作
         → 产品生成服务
         → 受控产品写入与保存后核验
```

## 三个内部边界

### 产品生成服务

入口：`src/main/planning/product-generation.ts`。

`ProductGenerationService` 接收产品读取、结构化生成、受控运行时和资源核验回调。它负责：

1. 完整用户行程优先规范化投影；其它输入由结构化生成器处理。
2. 清除模型未经核验的新 POI 声明。
3. 按阶段白名单、schema、文案与锁定约束写入。
4. 执行图文、套餐名、指导价、库存等既有确定性补全。
5. 保存后回读核验；行程在资源核验前后检查结构与原始行程约束。
6. 合并生成和补全结果，避免同一模块同时显示已接受与旧拒绝。

只有图文和商业阶段沿用本地兜底；其它生成错误继续交给持久化调度处理。指导价仍是可审核的本地草稿，不能当作供应商真实报价。

`agent/integration-generate.ts` 只组装依赖和工具协议。浏览器依赖在执行时读取，避免初始化期间保存尚未就绪的实例。

### 准备阶段规则

入口：`preparation-completion.ts`；动作规则：`preparation/policy.ts`。

产品事实由检查器归纳为带 `code / stage / node` 的缺项；基础信息、商业内容、资源、交通和派生文案各自维护检查。界面文案在检查边界完成分类后，不再参与动作权限判断。

`evaluatePreparationCompletion` 统一返回当前阶段、当前节点、缺项、允许动作与锁定条件。Agent 的工具门禁、任务上下文、完成门和自动动作读取同一份规则。

自动动作仍限于既有的行程生成、POI 核验、酒店核验和推荐理由补全。Agent 保留人工选择、重试预算、模型修复窗口、最终审批及事件记录；该重构不扩大自动业务决策范围。

副标题或运营备注缺失时，completion 阶段允许调用相应 basicInfo 生成器，无需重新开启 foundation。

`preparation/director.ts` 保留原有进度指纹算法；同样的产品事实重启后得到同样的动作和重试指纹，避免重置既有自动尝试预算。

### 兼容进度转换

入口：`planning-state-projection.ts`。

旧界面读取 `PlanningGenerationState` 时，一阶段下的全部必需节点必须完成或明确跳过，才计为完成。缺失、失败、阻塞、失效或待处理节点都阻止该阶段完成。

节点状态只能证明执行进度，因此转换不会伪造 accepted 模块。旧快照的整体 completed 标记与节点不一致时保持可恢复状态；产品就绪与审批仍以当前产品核验为准。

## 数据与授权边界

- `products.product_json`：当前产品内容。
- Agent snapshot：当前运行、事件、重试和授权。
- `planning_generation`：旧编排入口的兼容状态；正式 Agent 入口不启动旧编排器。
- 资源与 VBK 回读：对应平台事实，不能由模型声明替代。

`meetingCity` 保持创建时的城市锚点，`destinationCity` 与其一致；行政字段使用无尾缀短名。原行程的日期、顺序、点名地点、备选关系和明确活动保留，后勤安排规范化到相应字段时同样必须保留内容。

准备完成才允许最终确认。VBK 自动录入、审批守卫和草稿边界继续使用既有执行器。

## 验收门

- 产品生成：生成错误、写入拒绝、未实际保存、资源核验后损坏都不能返回虚假接受结果。
- 行程：完整输入优先投影；锁定行程、城市和已核验 POI 保持；服务活动转换后内容不丢失。
- 准备：缺项类型决定动作权限；早期审批被拒；旧自动预算与续跑保持稳定。
- 进度：同阶段部分节点成功不能标为阶段完成；空模块摘要不伪造业务接受证据。
- 兼容：原调用方路径、工具名和参数保留；类型导出与运行时导出分开。
- 工程：类型检查、单元回归、规划与 Agent 重点回归、构建、差异检查通过；修改和新增文件均不超过 350 行。

离线和本地服务模拟验证不能替代真实模型服务、登录账号资源查询或 VBK 写入的验证。
