# 行程规划与 VBK 录入稳定性验收矩阵

日期：2026 年 10 月 4 日。状态：完整验收方案已定义；行程规划首轮已实现，本地结果单列于[首轮执行与验证](./2026-10-04-itinerary-planning-first-pass.md)。本表供逐轮执行和独立验收，配套[执行方案](./2026-10-04-planning-vbk-reliability-plan.md)及[证据清单](./2026-10-04-planning-vbk-reliability-evidence.md)。

所有用例采用“通过、不通过、待环境、未执行”。以下 A01 至 A32 均为完整工作包的验收标准，目前没有逐项完成。首轮 P01 至 P08 覆盖其中的局部行程行为，不将其扩大填成完整 A 用例通过；调查中已有代码或旧验证也不能自动填为通过。

追加业务约束：运营明确命名的景点（含所有二选一备选）不可由 Agent 删除。真实查询未命中时保留原日、原位置并展示手动 POI 入口；仅运营明确手动删除该处的可信记录允许缺失，不能豁免同日其他同名景点。已有平台 ID 的本地修改不能沿用旧方案录入授权。本轮对应 D01 至 D07 的隔离与实际产品验证，单列于[日喀则个案记录](./2026-10-04-itinerary-case-06469f84.md)，不改变 A01 至 A32 的完整验收口径。

## 用例与判断标准

| 编号 | 工作包与层级 | 操作或故障 | 期望结果与失败条件 |
| --- | --- | --- | --- |
| A01 | R0 只读诊断 | 联合读取一个已恢复、一个规划失败、一个创建未核验产品 | 输出当前 run、原错误、已写与未写边界、版本及安全恢复建议。将历史失败误认当前失败、只有产品 ID就判成功，均失败。 |
| A02 | R0 证据与版本 | 固定源码指纹、隔离夹具和应用构建标识 | 同一输入可重现原缺陷；源码、运行版本、真实验证边界明确。使用生产库写入或把旧协议文档当当前事实，均失败。 |
| A03 | R1 工具生命周期 | 查询工具永不返回；暂停后返回迟到结果 | 在配置期限内停止等待，保留已完成项，旧结果不更新新 run；不得永久 running。 |
| A04 | R1 语义进展 | 模型换参数反复查询或反复写同一方案 | 必要缺项没有前进时按共享预算停止，显示准确当前原因；换参数或诊断文本变化不得重置预算。 |
| A05 | R1 长任务 | 价格库存分批运行，有心跳但当前批次不返回 | 展示当前批次和已回读数量；心跳不冒充业务进展；超过当前批次期限后进入对账，不能重复提交。 |
| A06 | R1 流式性能 | 对历史最大快照及隔离长对话回放 60 秒流式输出 | 流式 checkpoint 每秒不超过 2 次；稳定工具、授权、结果立即落盘；纯流式片段不改变业务版本、不触发业务镜像 PATCH。事件和重启后历史完整。 |
| A07 | R1 写入取消 | 写操作派发后超时或用户暂停，再提交继续命令 | 下一步停止，旧操作被隔离或等待安全结束；旧写未核清前无第二个执行器。仅用 Promise.race 后解锁重写即失败。 |
| A08 | R2 服务端保存后丢回执 | 隔离服务器完成非幂等写入，再模拟 context loss 或网络断开 | 写接口只有一次派发；后续仅独立回读，匹配则 verified，不匹配则未知或冲突。native fallback 第二次写即失败。 |
| A09 | R2 Retry After | 查询与外部写分别返回带等待秒数的错误 | 查询有预算退避；已派发非幂等写先对账，不按文本盲重发。等待到期后预算仍累计。 |
| A10 | R2 权限与壳创建 | 返回壳 ID，基本信息回读随后返回 40010001 | 壳 ID及供应商编号落盘，进入只读核对；不创建第二个壳，不显示完成。账号、来源和业务上下文诊断准确。 |
| A11 | R2 响应合同 | 注入 HTTP 200、Ack Failure、未知 Warning、空查询、缺 ID回执 | 按各端点合同区别业务失败、有效空查询和无效写回执；native 与页面诊断一致。只看 HTTP 或一律将空列表认失败均不通过。 |
| A12 | R2 持久化失败 | 分别在 prepared、dispatched、verified 保存时注入 SQLite 错误 | 禁止后续写入；保留已知事实并显示持久化失败。吞异常后继续或把不能落盘的成功作为可重试状态即失败。 |
| A13 | R2 文案与模型拒绝 | 平台反馈非法词；另注入模型输入 422 | 平台文案复用最多两轮字段级修复并回读，原事实资源保持；模型拒绝单独分类，不原样无限重试，不创建平台产品。 |
| A14 | R3 酒店部分完成 | 第 1 个住宿段回读成功后模拟进程退出，新进程重新加载库及远端 | 只补缺少的住宿段；已保存候选、顺序和资源内容不丢失。允许 ID重映射；内容变化则停。 |
| A15 | R3 价格部分完成 | 部分日期成功、批次超时、退出重启 | 回读完整价格库存语义后仅补缺日；已确认日期不重写，不正确价格不能靠正数或数量凑足通过。 |
| A16 | R3 阶段证据失效 | 已完成行程后修改天数、酒店候选、套餐价格；另修改派生平台 ID | 实质变化失效对应证据及依赖，必要时重确认；派生变化有白名单 diff，原授权继续。旧 completed 不能直接跳过变化后的阶段。 |
| A17 | R3 基础信息核对 | 远端产品编号和供应商编号正确，但城市、天数或本次期望字段不同 | 返回冲突而非 reconciled；不能仅靠编号确认 basic 已完成。 |
| A18 | R3 交通子产品 | 子产品已创建后中断；注入无资源跳过与详情保存失败两种情况 | 恢复不重建子产品；验证关系、启用、节点与最终读回。合法跳过有证据；技术失败保留待办，不能无条件成功。 |
| A19 | R4 状态一致 | 草稿权威保存后存在旧 paused/failed snapshot；另有当前新规划 run | 草稿结果、当前 run和历史事件分别展示。旧告警不会遮盖当前结果，新 run未完成不会被旧草稿成功覆盖。 |
| A20 | R4 用户废弃 | 完成草稿后用户废弃另一轮 Agent任务 | 草稿仍显示保存事实，废弃 run保持 abandoned；不得强制将废弃任务改成 succeeded或将草稿说成未保存。 |
| A21 | R4 等待与必需资源 | 缺必需酒店或账号登录；缺逐景点配图；只完成本地规划 | 必需项给一次明确动作；配图缺少不阻塞；本地 ready展示等待确认，不显示VBK完成。 |
| A22 | R4 历史兼容与并发 | 旧 phase名/旧checkpoint；同产品双击恢复；不同账号切换 | 兼容后仅一个有效执行器，账号变化阻止旧客户端；不从未知写入自动重跑，不清空已完成事实。 |
| A23 | R5 全新用户路径 | 从真实桌面创建入口输入两条不同完整行程 | 每条经过规划核验、正式确认、全部适用阶段及独立回读；当前版本连续两次无人工救场。API JSON直跑、复制数据库和旧草稿续跑不能替代。 |
| A24 | R5 退出与再进入 | 全新草稿完成后正常退出应用并重启，再读SQLite与平台 | 草稿、当前已完成run和适用阶段证据一致；城市、天数、POI顺序、酒店、套餐、价格库存、图文、条款及资源读回保持。 |
| A25 | R5 产品类型与输入 | 完整行程、简短想法、纯自由活动日、二选一、跨住宿城市；按实际使用产品类型验收 | 行政短名和城市锚点不变；不伪造POI，不重排行程；车辆阶段按类型适用。未真实验证的类型标待环境。 |
| A26 | R5 交付报告 | 汇总全部用例及真实平台检查 | 启用/跳过/失败分别计数；记录代码版本、本地与平台ID、授权范围、证据和剩余项。未提审、未发布状态由平台读回确认。 |
| A27 | R1 不必要提问 | 模型询问继续、重试、生成副标题、推荐理由或普通审核指导价 | 程序返回并执行确定性下一动作，pendingInput为0；不得仅自动填“继续”后仍停止。正式授权另行保留。 |
| A28 | R1 重复答案复用 | 用户已确认酒店、封面或接送要求；换措辞、questionId、生成不相关模块及重启后再次询问 | 同字段及依赖语义复用已保存答案；不同账号隔离，新明确指令覆盖旧答案。旧问题机器消解后自动推进，不暂停要求继续；合格人工封面沿用并继续。 |
| A29 | R1 规则覆盖与例外 | 已有明确联系人、产品类型、纯服务节点、二选一及可选缺图 | 自动采用规则并继续；变换措辞不影响决定。多个真实可选且影响业务的候选不得凭第一项乱选。 |
| A30 | R1 已知恢复闭环 | 连续注入同一非法词或酒店候选技术故障，使用已验证恢复器 | 有限定修复、持久化、回读及自动续接，用户额外介入为0；旧已完成阶段不重跑，恢复预算跨重启不重置。 |
| A31 | R1 必要问题保留 | 输入有核心冲突且无法推导，或需要改变已确认价格/酒店/行程 | 合并一次业务问题，列差异及已查证据；正确保留正式录入确认。少问不能以伪造事实、丢原意或越过授权实现。 |
| A32 | R1 恢复耗尽与重复故障 | 未知协议错误或同因恢复预算耗尽，模型再问“要不要继续”；另测试登录前置满足及用户主动暂停 | 显示精确阻塞，不提无效继续问题、不盲重发；机器前置满足且账号及授权适用时自动恢复，未知写先对账。用户主动暂停或废弃始终不自动恢复。 |

## 性能门的测量口径

A06 使用隔离副本，先记录同一机器和相同输入的基线，再使用当前最大历史快照以及含至少 100 个工具事件的长对话夹具。记录快照字节、SQLite写次数、业务产品更新次数、业务镜像请求次数、写入 p95和主线程事件循环延迟 p95。

初始性能目标：流式期间主线程事件循环延迟 p95低于 100ms、持久化 p95低于 50ms。若硬件基线已超限，记录实际值和原因再调整门槛；不能先放宽门槛掩盖退化。未测量时不得填通过。业务事件同步依现有产品合同，纯流式阶段业务镜像应为 0次，稳定事件只同步实际变化。

生命周期用例采用可控时钟和短测试期限验证，不让单元测试真的等数分钟。真实批量流程按生产类别期限运行，记录当前 batch的有效进展；禁止把流式输出或重复心跳当作业务完成。

## 必须保存的验收记录

每个用例一条记录，至少包含：

- 用例编号、执行日期及人员、状态、代码与应用构建版本。
- 输入夹具、产品类型、账号代号、本地 productId、runId、approvalId与阶段/操作ID。
- 预期值、实际值、错误来源、写入次数、权威回读来源与时间、持久化检查点。
- 问题文件及修复位置、是否发生人工介入、重启后结果及剩余事项。

诊断材料使用脱敏响应和字段摘要，禁止保存 Cookie、token、完整鉴权头和个人联系方式。日志超出保留窗口时写“证据缺失”，不能据此推定从未失败。

## 现有验证入口与新增要求

现有入口：`npm run check`、`npm run build`、`npm run test:integration`、`npm run test:browser`、`npm run test:e2e`，以及相关文件的定向单元测试。`npm test` 默认只选变化相关单元测试，不等于全量验证。

现有 `test:e2e` 依赖 `VBK_LIVE_E2E=1` 及外部写入配置，默认跳过。执行它会创建真实母产品与交通子产品，必须另获明确授权；本次规划没有运行。现有用例自身设置 300 秒，运行器默认 60 秒，实际优先级和长流程表现须在实施时核验，不能仅据静态代码认定已超时失败。

新增测试必须通过生产支持的桌面创建、Agent、审批和确定性录入入口。浏览器 fixture及隔离API服务器用于可控故障注入；真实平台用例用于证明协议与持久化闭环，二者不能互相替代。

建议保留按用例编号选择的诊断和回放命令，默认只读或隔离，live写入显式开关且清楚列出动作。此处是待实施接口要求，不是当前已存在命令。

## 真实验收动作范围

实施和离线门控完成后，提交一份具体真实验收清单：指定账号，创建两条全新未提审私家团，写入销售控制、基本信息、图文、行程、套餐、价格库存、酒店、用车和条款，执行独立回读与最终预检，退出重启后再核对。交通仅在测试输入及授权范围明确启用时创建子产品。

若验收当前旧草稿，清单必须明确原本地及平台 ID、已完成阶段、仅需补写的阶段和对子产品的动作。不能用“执行验收”笼统授权替代具体产品写入范围。无论新建或恢复，终态保持未提审、未发布，不删除测试产品。

修复后全新完整成功必须重新连续计数。两次之间发生需人工救场、重复写、错误成功或核心约束丢失，都归零；单元测试绿、一个阶段成功及已有草稿续跑均不能补计。
