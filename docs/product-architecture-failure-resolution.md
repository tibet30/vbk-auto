## 业务边界回归

- 持久化保存后，匹配华阳古镇 POI 的住宿城市修正为平台短名，产品 `meetingCity` 和 `destinationCity` 仍为锁定值。
- 用户另选汉中住宿时，旧华阳 POI 不能改回旧住宿锚点；未核验 POI 不能覆盖已保存住宿城市。
- POI 的海西行政上级不能覆盖已核验的茫崖住宿城市；完整复跑发现这一边界后，将修正收窄为更具体区县证据纠正继承接团城市的旧默认值，并重新运行全量。
- 缓存缺少匹配住宿锚点时继续拒绝；市区住宿仍要求城市锚点证据，景区距离不能被重复解释为市区距离。
- 未允许降档时只查目标等级；允许时按原住宿地逐级查询，网络失败直接停止，不重启整轮评级查询。
- 现有酒店许可、最新回答、距离限制、逐晚评级及查询期间人工修改保护均保留。

修改测试中的两份超长文件按职责拆为邻接 cases，原测试入口及相对源码依赖保持稳定，所有新增/修改文件不超过 350 行。
类型检查同时修正工作台旧接口能力检查的表达方式，保留运行时兼容分支。

首次复跑额外发现一项旧测试仍从 IPC 源码提取续跑文本。现改为实际调用 `ProductTaskScheduler.resume` 并等待 Agent 空闲，验证历史授权复用、直接交给确定性执行、模型调用为零及结构化重试字段。对应 8 项回归通过；修复后从头重跑全量，未把中断的运行当作验收结果。
