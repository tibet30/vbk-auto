# 产品架构迁移与本地验收

本文件描述当前未提交的五阶段重构。真实业务库迁移、VBK 写入、代码提交和发布需另行获得授权。

## 存储切换

启动构造 `VbkDatabase` 时，在任务恢复、模型调用和浏览器初始化前应用 `0017_product_architecture`。
旧库先通过 SQLite `VACUUM INTO` 生成包含已提交 WAL 内容的一致性副本，文件名为原库路径加 `.before-architecture-<UUID>.sqlite`。
首次新建空库无需历史备份；迁移成功后重复启动不再备份或转换。

一个事务内完成新表及列、产品数据拆分、授权等价判断、写入守卫和迁移标记。任何数据无法安全解析或重新组合不等价时，报告表及产品 ID，回滚全部结构和数据修改。
备份位于事务外，不随回滚丢失；失败重试可能增加一份备份，但不会覆盖已有副本。

| 记录 | 新位置或规则 |
| --- | --- |
| 本地方案、运营选择、人工删除凭证 | `products.product_json`；`plan_version` 与兼容 `product_json_version` 同步 |
| 每日酒店候选、行政节点核验、平台酒店镜像、交通端点可用性 | `product_resource_evidence`；`evidence_version` 独立递增 |
| 运行诊断 | `product_runtime_diagnostics`；不改变方案版本或最终确认指纹 |
| Agent、消息、核查任务、录入历史 | 原表保留；不另存一份执行检查点 |
| 展示更新顺序 | `products.view_revision`；相关耐久事实提交后递增 |
| 旧重试入口 | `retry_mode` 结构化保存；中文文案仅在一次性历史转换中识别 |

产品原始 JSON 不经平台 schema 过滤迁移；未知扩展字段保留。历史资源标记为 `legacy`，缺失来源或核验时间继续缺失。
业务读取通过组合投影兼容旧工作台和平台输入；方案、证据、诊断在底层分别持久化，避免长期双写旧 JSON。

## 历史授权

只有旧指纹匹配、转换前后组合内容等价、账号和范围一致且无不支持范围、所属运行及意图明确、无结果不明写入时，才切换授权指纹。尚未返回的已发出工具或运行中的录入阶段也按结果不明处理。
原授权 ID、时间、范围和事件保留，增加包含旧指纹的 `migrationProof`，不会生成新审批事件。
无法证明等价的授权标为失效，仅暂停其实际所属的非终态运行并要求重新确认；历史审批不得干扰其他当前运行，全部录入检查点保留。

## 写入与恢复边界

- 产品命令捕获读取版本或字段基线；异步结果仅应用其变化，目标或查询条件过期则返回可重试冲突。
- 人工字段、AI 和资源命令的严格任务确认与产品保存在同一事务中，保存后重读并广播。
- 执行服务在 Agent 和自动录入事实保存处投影任务状态；查询及广播只读取。
- 母产品需要所需阶段及预检的持久化完成证据；交通子产品分别需要 `verified` 和 `finalReadback`。
- 永久废弃任务不会被回调复活。普通迟到回调不能降低成功终态；执行服务可依据新耐久事实纠正旧的错误投影。
- 平台业务适配保留资源域的具体类型；查询空结果与登录、网络、解析、业务失败分开。
- 写入在共享页面锁内检查账号、授权和取消；适配器只调用一次。结果不明持久化到 Agent，恢复先调用既有只读核查策略。
- 新工作台通过统一快照读取、订阅及恢复。旧 IPC 保留兼容外观，首次响应与事件均使用持久化版本排序。

## 旧版保护及回退

新版数据库写入触发器要求当前连接注册 `vbk_architecture_writer()`。旧版程序未注册该函数，写入失败，不能继续改动新版库。
需要回到旧版时，先关闭新版及所有 SQLite 连接，另行授权后用迁移前一致性备份恢复旧库；不能以旧表结构覆盖已迁移库。
备份恢复不会包含迁移之后的新业务操作，必须由运营确认需要保留的数据。

## 验收证据入口

重点测试位于 `test/application/product-architecture*.test.ts`、`product-command-service.test.ts`、`product-execution-service.test.ts`、`platform-operation-service.test.ts`、`product-workspace-snapshot.test.ts` 及 `test/workflow/workspace-snapshot-store.test.ts`。
覆盖 WAL 备份、重复启动、非法历史记录回滚、授权等价与失效、旧版拒写、并发字段写入、核查事务回滚、母子结果分离、结果不明阻止重放、账号与事件顺序隔离。
架构门位于 `test/infrastructure/product-architecture-boundaries.test.ts`，检查受控入口、平台边界和本次全部新增及修改文件的 350 行硬上限。

全量入口是 `npm run test:all`；`npm test` 仅选变化相关测试。真实平台验收单独执行，母产品和每个交通子产品分别读取持久化回读证据。

启动中断、受控指纹事务及补充回归详见 [架构与业务一致性复审](product-architecture-review.md)。
