## 发现与修复

| 问题 | 修复及业务影响 |
| --- | --- |
| 无迁移登记表的既有库未备份 | 以实际用户表判断旧库；任何已有数据先一致性备份，空库仍不产生历史备份 |
| 历史研究证据或录入阶段结构损坏未阻断转换 | 校验证据数组、Agent 事件及阶段结构；错误带表和记录归属，事务回滚 |
| 旧运行的审批失效会暂停当前等价运行 | 仅暂停审批实际所属的非终态运行；旧事件身份、时间仍保留 |
| 历史授权只检查所需范围，未拒绝额外不支持范围 | 使用领域范围规则；未完成的已发出工具或正在执行的录入阶段也不能证明授权迁移等价 |
| 录入期间/恢复时直接接受或刷新任意指纹变化 | 每次写入和完成必须匹配指纹；仅受控产品事务可推进匹配的既有授权，恢复/暂停/完成不能采用新的业务方案 |
| 受控回填可能基于请求结束时的新状态覆盖人工修改 | 自动录入上下文保留开始时的基线，提交只应用该基线上的变化，冲突拒绝覆盖 |
| 同一产品多条运行记录在重启时被覆盖成同一份 | 按运行 ID 和产品 ID 更新各自记录；历史 ID、检查点分别保留 |
| 应用在写入过程中退出后可能直接重试 | 发出前持久化 `write_dispatched`；重启时正在执行的阶段或无返回记录的已发出调用转为结果不明，先只读核查。已核查记录耐久结案，不在下一次重启重复阻断 |
| 基础核查仅凭产品编号/供应商编号就确认成功 | 同时核验城市 ID、城市名和天数/晚数；通过后事务保存完成断点及基础保存事实，下一次从剩余阶段继续 |
| 交通失败把已验证母产品降为未完成，或缺少恢复动作 | 母产品依据自己的阶段证据；子产品依据各自 `verified/finalReadback`，恢复动作分别计算 |
| 已废弃 Agent 被迟到成功事实投影为成功 | 废弃优先，不能被母产品成功回调复活 |
| 无业务版本的兼容整包保存可绕过命令并发规则 | 必须提供与当前产品一致的业务版本；缺失或过期都返回冲突 |
| 站点接口集合缺失变成正常空结果，登录错误码丢失 | 缺少集合报协议解析失败；正常空数组仍有效；错误码保留供登录分类 |
| 工作台操作响应绕过快照排序，历史失效确认卡仍占用恢复入口 | 操作后重新合并权威快照；失效卡清理后保留检查点，重新确认当前方案 |

## 授权与断点规则

受控授权推进只适用于同一运行、同一意图、正在运行、无不明写入且旧指纹匹配的事务。
价格库存、天数/晚数、城市锚点、酒店要求及候选、景点/POI 选择、酒店档次和车辆选择不得通过此路径改变授权。
平台镜像及生成编号继续使用有效方案投影；允许的确定性文案回填由匹配基线的事务推进指纹，保留原授权 ID、时间、范围和事件。
普通人工/AI/资源业务修改不推进授权；发生修改后，写入、恢复和完成均停止并要求确认。

历史授权缺少等价证明时标为失效。正在执行但未确认结果的阶段，以及已发出而无结果的工具不能当作“未写入”。
无法确认的产品壳不会自动重建；不支持自动核查的阶段继续保留现场。
基础信息的只读核查通过后写入耐久完成断点，防止恢复时重复提交；部分交通结果不提升为全体完成。
