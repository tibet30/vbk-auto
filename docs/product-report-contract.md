# 产品本机保存与问题诊断上报契约

目标：帮助开发者在远端分析用户遇到的问题，并拿原始输入在自己的本地复现。
用户已选择：产品权威存储改为本机，服务端只接收诊断及独立的 AI 消耗汇总。此契约取代之前的完整产品快照上报方案。

## 信息边界

| 类别 | 是否上传 | 内容与理由 |
| --- | --- | --- |
| 原始输入 | 创建时上传一次 | 目的地、产品形态、天数、用户想法；以后不覆盖 |
| 关联身份 | 是 | 本机产品 UUID、名称；用户归属由登录令牌在服务端确定，不额外上传手机号或平台账号 |
| 失败现场 | 失败时上传 | 事件 ID、运行 ID、步骤、工具名、脱敏参数、错误、发生时间、失败前执行指令 |
| 软件与模型 | 随输入/失败上传 | 采集时软件版本、操作系统、架构；模型/供应商优先从失败之前的调用用量事件获取，不上传用量账本 |
| 生成的产品正文 | 否 | 基础信息、行程、资源、图片引用、报价、库存留在本机；失败工具参数可能包含与该调用直接有关的片段，并受大小限制 |
| 会话全文、核查任务、候选池 | 否 | 本机保存；诊断只保留失败前最后一条执行指令 |
| AI 消耗汇总 | 是 | 累计与最近一轮 Token、人民币估算费用、模型与计价依据；逐条用量账本留在本机 |
| 规划、平台检查点、自动录入恢复状态 | 否 | 本机保存，继续支撑恢复与避免重复录入 |
| 完整日志、截图、执行耗时、缓存版本 | 否 | 本机保存 |

发送与接收双方对白名单诊断字段限长并脱敏。工具名最多 120 字符、错误最多 2000 字符、参数超过 8000 字符改为标记了 `truncated` 的预览。服务端拒绝未知顶层字段和超过 48KB 的请求。

## 提交时机与一致性

1. 产品 CRUD、规划和用量经 `createLocalProductService` 在 SQLite 保存；产品读取不再从服务端回包覆盖本机。
2. 创建和失败经独立 `/api/extension/desktop-diagnostics` POST 上传。普通字段更新、正常进度、成功完成都不触发新诊断上传。累计 AI 消耗变化时，另经 `/api/extension/desktop-usage` POST 上报汇总；不恢复完整产品云端写入。
3. 本机 outbox 按用户 ID 和事件 ID 持久化，重复观察相同事件不重复发送。失败不会因恢复成功而从服务端消失。
4. 诊断接口异常、断网或回包未确认保存时，保留队列，启动及每分钟重试；产品保存和执行不等待网络成功。
5. HTTP 200 不代表保存成功：必须确认 `code=200`，并核对回包产品 ID 与事件 ID，才能记录发送回执。
6. 账号切换仅发送该账号的待传事件；原始输入和失败事件都以服务端账号为边界幂等保存。

## 协议边界

新数据存入独立的 `DesktopDiagnosticCase` 与 `DesktopDiagnosticFailure`，不会与旧产品快照混存。

历史 `/desktop-products` 数据通过只读 GET 按账号迁入本机一次；已有本机产品只补齐归属、规划、用量和平台账号元数据，不覆盖其产品内容、消息、版本或运行日志。旧云端接口及历史数据保留兼容旧版本，新版本产品链路不再调用云端 POST/PATCH/DELETE。迁移失败可重试，不阻塞新本机产品操作。

后台入口为“扩展管理 → 桌面问题诊断”。列表显示用户、原始输入摘要、累计 Token、人民币估算费用、最近问题、失败次数和上报时间；详情优先展示原始要求、错误、执行指令、版本与模型，工具参数按需展开。可下载最近一次或指定历史失败的 JSON 复现资料。页面只读。

用量上报包含当前产品累计和最近一轮的调用数、耗时、输入/输出/总 Token、缺失标记、人民币估算费用，以及模型/提供方汇总和本地计价依据。数据口径与桌面 `withAgentUsage` 一致，不上传逐条调用账本、对话或产品正文。币种固定 CNY，费用明确为估算；无法折算时为 null，不能当作零费用。

用量复用按账号持久化的 outbox，以产品和汇总内容的哈希去重；断网和未确认回包继续补传。后台按账号及本机产品编号保存最新汇总快照，重复请求不累加，旧采集时间不覆盖新数据。必须核对回包 clientId 和 eventId=reportId 后记录回执。先收到用量时允许创建空输入的关联记录，后到的原始输入仅补齐一次，随后保持不可变。

原始输入支持从头复现与故障定位，不保证重现当时平台资源、登录状态或模型的随机生成结果；版本字段表示采集软件版本，历史事件未记录其执行版本时不能据此假设二者一致。

## 验收证据

- `test/infrastructure/local-product-service.test.ts`：本机存储及重启读取、规划保留、账号隔离、版本冲突、本机删除、历史迁移和断网操作。
- `test/infrastructure/product-diagnostic-reporter.test.ts`：仅输入/失败上传、脱敏、重复事件与成功恢复、断网重启补传、回包确认、账号隔离。
- Tibet `api/tests/test_desktop_diagnostics.py`：实际接口持久化、原始输入不可变、失败历史和幂等、契约限长、后台页面与权限、指定失败资料下载。
- 本地跨应用演示：桌面组件实际 POST 到隔离 Django 服务，后台实际保存并下载回读；浏览器检查列表、详情、展开参数、下载及窄屏。

验收边界：本地代码、隔离数据库、跨应用协议与浏览器。未部署、未操作生产业务数据、未进行真实用户设备的升级迁移。
